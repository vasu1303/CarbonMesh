# CarbonMesh Project Context

Last updated: 2026-10-01

## Authoritative context

The repository-wide coding-agent contract is [AGENTS.md](../AGENTS.md). This
document is the human-readable project summary. When they differ, the latest
explicit team instruction and then `AGENTS.md` take precedence.

CarbonMesh is a four-module hackathon proof of concept:

1. Measurement and Carbon Intelligence.
2. Reporting, Disclosure, and Assurance.
3. Procurement and Circularity.
4. Forecasting, Scheduling, and Dispatch.

They share one semantic catalog, immutable context envelope, deterministic fact
binder, append-only carbon ledger, generic Preview-Approve-Commit workflow, and
bounded agent trace.

## Product outcome

CarbonMesh turns activity and grid data into traceable carbon facts, uses those
facts to support a limited disclosure, compares feasible lower-carbon supplier
products, recommends a lower-carbon operating window, and pauses consequential
outputs for human approval.

The model may contextualize, plan, decompose claims, and draft templates. It may
not calculate business numbers, issue SQL, invent citations, relax constraints,
approve decisions, place orders, or actuate equipment.

## Golden scenario

All demo data is synthetic and visibly labelled.

| Element | Contract |

## Database contract

The approved target is 46 tables across eight schemas:

| Schema | Count |
| --- | ---: |
| `core` | 9 |
| `semantic` | 5 |
| `ai` | 2 |
| `carbon` | 10 |
| `ledger` | 4 |
| `assurance` | 6 |
| `procurement` | 5 |
| `dispatch` | 5 |

The implemented model moves agent runs to `ai`, approvals to `core`, fact
bindings to `ledger`, renames the physical Procurement recommendation table,
and adds timestamped grid points plus Assurance and Dispatch storage. Exact
names and lifecycle rules are in [database.md](architecture/database.md).

FastAPI startup performs no DDL, migration, seed, or reset. Local Docker URLs
may disable TLS only for approved local hosts; all remote PostgreSQL URLs require
verified TLS. The clean 46-table bootstrap is complete and is the normal path
for fresh/disposable development databases. Database migration is not a
remaining feature assignment. If an older live database must retain its data,
an operator must separately design and rehearse that transition against a
confirmed disposable target with rollback available.

## Module rules

### Measurement

Use exact formulas:

```text
Scope 2 kgCO2e = kWh * gCO2e_per_kWh / 1000
purchased-material kgCO2e = kg * kgCO2e_per_kg
```

Hourly data must align to a real grid point; missing intervals are explicit.
Confidence v2 is source quality 35%, method fit 25%, temporal match 20%, and
completeness 20%.

### Assurance

Claims are atomic and evidence-bound. The model cannot free-type citations.
Validators enforce fact existence, context equality, requirement relevance,
comparability, citation resolution, no unbound numbers, evidence threshold, and
staleness. Unsupported claims remain visible and cannot be approved.

### Procurement

Apply hard constraints first. Score feasible options with carbon 40%, evidence
25%, circularity 20%, and operational fit 15%. Cost remains a hard constraint.

### Dispatch

Enumerate complete consecutive windows and minimize deterministic emissions
under earliest start, latest finish, duration, delay, capacity, and blackout
constraints. Earliest start wins ties. Recommendations are advisory only.

## Agent runtime

Target graphs: orchestrator, Measurement, Assurance, Procurement, Dispatch.

Budgets:

- Single module: at most 3 model calls and 8 tools; 15-second target.
- Four-module flow: at most 6 model calls and 20 tools; 45-second target.
- Approval resume: 0-1 model call and at most 3 tools; 10-second target.
- One structured-output/tool repair per stage; no autonomous retry loop.

Typed stops include success, clarification, no data, unsupported, policy block,
provider unavailable, budget exhausted, validation failure, approval required,
no feasible option, and stale.

## Delivery gate

The build is complete only when one clean reset drives all four modules; every
number traces to live source/calculation/ledger evidence; an unsupported claim is
blocked; procurement and dispatch preserve hard constraints; generic approvals
reject stale payloads; agent budgets and telemetry are visible; and the result
replays deterministically on a clean machine.
